# Character Mannequin

Процедурный капсульный персонаж для проектов на Three.js. Модель создаётся кодом: 78 оболочек, скелет из 85 костей и пять материалов. FBX-файлы для работы не нужны.

Пакет не создаёт сцену и не импортирует Three.js самостоятельно. Хост передаёт свою копию `THREE`, поэтому можно использовать одну версию библиотеки во всём приложении. Данные рига и привязок доступны и без рендера.

## Установка

После публикации репозитория:

```bash
npm install git+https://github.com/Kilyakus/character-mannequin.git
```

При закреплении в приложении рекомендуется указать конкретный коммит. Пакет не содержит сборку Three.js: установите её в приложении отдельно.

## Использование

```js
import * as THREE from 'three';
import { createCapsuleMannequin } from 'character-mannequin';

const character = createCapsuleMannequin({ THREE });
const body = character.build();
scene.add(body.group);

const { bindings, missing } = character.bindings(body.skeleton);
console.log(body.shellCount, character.rig.bones.length, missing);
```

`body` содержит `group`, `mesh`, `armature`, `skeleton`, `bones` и `shellCount`. Модель создаётся в исходных единицах; размер, положение и поза задаются хостом.

### Палитра

```js
const palette = character.paletteFromColor('#4c73c9', { face: '#151a20' });
const variant = character.build({ palette });
scene.add(variant.group);
```

Можно задать отдельные цвета `porcelain`, `secondary`, `joint`, `accent` и `face`. При смене палитры форма модели не меняется.

### Данные и привязки

| API | Назначение |
| --- | --- |
| `character.rig` | имена, иерархия и rest-матрицы костей |
| `character.boneMap` | карта 21 семантического узла к именам костей |
| `character.bindings(skeleton)` | привязки узлов к костям конкретного скелета |
| `character.boneParts` / `partForBone` | сопоставление костей с частями тела |
| `character.paletteFromColor(color, overrides)` | палитра по базовому цвету |
| `character.materials(palette)` | описание пяти материалов |

Модуль `character-mannequin/character` экспортирует необязательный декларативный профиль; `character-mannequin/manifest.json` — манифест этого профиля. Они не запускают отдельный движок и не обязательны для работы фабрики.

## Демонстрация

Требуется Node.js 20.19+ и Git. Полностью распакуйте архив, затем откройте терминал в папке `character-mannequin`, где лежат `package.json` и `index.html`:

```bash
npm ci
npm run dev
```

Перейдите по адресу из терминала и не закрывайте окно сервера. На Windows можно также запустить `start-demo.cmd`: он проверит файлы, при необходимости установит зависимости и выведет адрес `http://127.0.0.1:5173/`. Если порт занят, остановите другую программу или запустите вручную на свободном порту:

```bash
npm run dev -- --host 127.0.0.1 --port 5199 --strictPort
```

Затем откройте `http://127.0.0.1:5199/`. Если сервер запущен в контейнере или на другой машине, необходимо пробросить порт и использовать адрес этой среды, а не `127.0.0.1` своей машины. Демонстрация входит в архив проекта, но не в npm-пакет библиотеки.

Демонстрация построена на [Preparatorio](https://github.com/Kilyakus/nodejs-preparatorio) (MIT): доковые области можно переставлять, а инструменты — отделять через меню. Preparatorio нужен только для разработки демо; фабрика персонажа от него не зависит.

### Позирование

- Выберите кость щелчком по модели, маркеру сустава или через дерево «Структура» и поиск. Вращайте кольца манипулятора либо задавайте углы X/Y/Z в инструменте «Поза». Для манипулятора доступны локальные и мировые оси; **Shift** включает шаг 15°.
- Доступны исходная Т-поза и три статических пресета «Спокойно», «Привет», «Шаг»; кнопка сброса возвращает выбранную кость в исходное положение. Это **FK-позирование**, не IK и не анимационный проигрыватель. Из-за жёстких весов при экстремальных углах возможны зазоры в суставах.
- Кнопки на сцене управляют ракурсами, суставами, скелетом и сеткой. Камеру можно вращать мышью и приближать колесом. `/` — поиск, `F` — общий вид, `R` — сброс выбранной кости, `Esc` — снять выбор (когда фокус не в поле ввода).
- Поза автоматически сохраняется в браузере. Её можно скачать и загрузить как JSON `capsule-rig-pose` версии 1 с исходными именами костей; поддерживается формат исходного Rig Lab. Некорректный файл не заменяет текущую позу.
- Инструмент «Палитра» меняет цвета, не перестраивая скелет.

Демо создаёт персонажа процедурно из `src/`; ни FBX, ни GLB в него не загружаются. Референсные файлы — только для редактирования и исследования.

## Исходники и референсы

- `reference/models/` — исходный `anime-base-tall.fbx`, редактируемый `capsule_mannequin.blend` и экспорт манекена `capsule_mannequin.fbx`. **В `.blend` также находятся скрытые исходные сетки Body и Head.**
- `reference/renders/` — оригинальные рендеры манекена.
- `reference/rig-lab/` — сохранённые исходники прежнего GLB-примера, его модель и документация для сравнения. Это архивный независимый пример, не рабочее демо и не зависимость пакета; собранный сайт не дублируется.
- `tools/build_capsule_character.py` — исходный Blender-скрипт сборки; `tools/export_glb.py` — экспорт манекена в GLB из `.blend`. Blender 4.0+ требуется только для этих операций. Рекомендуется записывать результаты в отдельную папку, чтобы не перезаписать исходники:

```bash
mkdir -p generated
blender --background --python tools/build_capsule_character.py -- --input reference/models/anime-base-tall.fbx --output-dir generated --no-render
blender -b reference/models/capsule_mannequin.blend --python tools/export_glb.py -- --output generated/capsule_character.glb
```

Исходные README в `reference/` сохранены как исторические документы: пути в них соответствуют прежней структуре архива. `reference/` и `tools/` находятся в GitHub-архиве, но не включаются в npm-пакет библиотеки.

### Проверки

`npm test` проверяет API, риг, геометрию и палитры; `npm run build` собирает демо. Для браузерного теста запустите демо на порту 5180 и выполните `npm run test:browser` (при необходимости сначала установите Chromium командой `npx playwright install chromium`).
